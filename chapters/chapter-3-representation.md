## Summary

In this phase, we translated the wireframe from Assignment 2 into a static HTML and CSS interface.

The goal was not to implement functionality, but to represent the structure, hierarchy, and layout of the interface.

This chapter focuses on the representation of the Fellowship Companion interface. It shows how the previously designed communication and clarification flow can be displayed as a static interface before adding interactive behavior.

---

## Artifact

Artifact 3 implements the capability **Information Clarification and Alignment**.

File: [Artifact 3 - Representation](../artifacts/artifact-3/artifact-3-presentation.md)

Files included:

- [interface.html](../artifacts/artifact-3/src/interface.html)
- [style.css](../artifacts/artifact-3/src/style.css)

The interface represents three states of the communication process:

1. Shared message
2. Clarification state
3. Resolved message

These states correspond to the interaction flow designed in Artifact 2.

The static interface shows how users can create a message, review received information, and understand where clarification would happen in the communication process. At this stage, the buttons and interface elements are only visual representations and do not include JavaScript behavior yet.

---

## AI Assistance

AI tools helped with structuring the HTML layout and improving the CSS styling suggestions.

However, the final structure and decisions were adapted to match the assignment requirements of a static interface without JavaScript.

AI support was mainly used to make the interface clearer, more readable, and more consistent with the original wireframe. The design was kept simple so that the structure of the system capability remained the main focus.

No interactive logic was implemented in this chapter, because the purpose of this artifact was representation, not functionality.

---

## Lessons Learned

This assignment showed how interface structure can represent system logic even without interactive behavior.

We learned that semantic HTML and clear layout help communicate the purpose of an interface effectively.

The static interface made it easier to understand how the communication flow from Artifact 2 could later become interactive. It also showed that visual hierarchy, spacing, and labels are important for explaining what users can do and how information moves through the system.

Overall, this chapter helped connect the wireframe and the later functional implementation by turning the concept into a clear static interface.
